Section 2
Odoo ↔ WooCommerce — How the Integration Actually Works
We use a proven, production-grade connector (Emipro's WooCommerce Odoo Connector, live since 2013, 10,000+ customers). Here is exactly what it does — nothing fabricated, sourced directly from the connector's documentation.
🛒

WooCommerce (SowEasy front end)

Your trade portal. Customers log in, browse, configure orders, and submit. WooCommerce stores the order and fires a webhook the moment it's placed.

⚙️

Emipro Odoo WooCommerce Connector

Installed in Odoo. Acts as the bridge. Uses WooCommerce REST API credentials + webhook listeners. Syncs in both directions via queue system with error logs.

📦

Odoo (your ERP — stays as-is)

Finance, inventory, sales orders, warehouse — nothing changes in how Jeremy and your team use Odoo day to day. Orders simply appear as Sales Orders automatically.

🔄

Webhook + Cron Jobs

Real-time order import via webhooks. Stock and product updates run on configurable schedules. Queue dashboard shows any failures with root-cause logs.

What syncs — and in which direction
Data Direction How Notes for SowEasy
New Orders WooCommerce → Odoo Webhook (real-time) Creates Sales Order in Odoo. Status: Processing or On Hold imported. Net terms — no payment gateway needed.
Order Status Updates Odoo → WooCommerce Manual / cron When you mark dispatched in Odoo, status pushes back to WooCommerce so the customer can see it.
Tracking Numbers Odoo → WooCommerce Automatic Export tracking numbers back to WooCommerce order — customer gets notification.
Stock Levels Odoo → WooCommerce Cron job (scheduled) Odoo is master of stock. WooCommerce reflects it. Note: SowEasy currently hides stock — this remains optional/off.
Products + Variants Both ways Manual export / import Matched by Internal Reference (Odoo) = SKU (WooCommerce). One-time setup, then maintained from Odoo.
Pricing (B2B tiers) Odoo → WooCommerce Pricelists Each trade account gets a pricelist in Odoo. The connector pushes the right price per account to WooCommerce. This is how your 3-tier pricing works online.
Customer Data Both ways Import / sync Existing 700–800 accounts: we import WooCommerce customers into Odoo and link them. New registrations sync automatically.
Refunds / Cancellations Both ways Webhook Cancel in Odoo → cancels in WooCommerce (and vice versa). Credit notes generated correctly in Odoo accounting.

Honest constraints — what the connector does not do out of the box

  • Automated PO email reading into Odoo — this is a separate AI agent feature, not part of the connector. Jeremy at Amarot tried this; we'd build it differently using structured parsing, not open-ended AI. Scope for a later phase.
  • Artwork proof approval workflow — the connector handles orders; proof rounds need a separate approval flow (email-based or a simple portal page). We keep this lightweight at launch.
  • Real-time stock display on SowEasy — you've deliberately hidden stock levels. We keep this off. Connector only pushes stock to Odoo when orders land.
  • Odoo Online (cloud) is not supported — connector requires Odoo On-Premise or Odoo.sh. Your current setup with Jeremy should confirm which you're on.

Section 4
Product Visualiser — How DynamicMockups Works
This is the part Jamie asked about most specifically. Here is exactly what the tool does, what its WordPress plugin covers, and what the API does behind the scenes. Nothing invented here — this comes directly from DynamicMockups' own documentation at docs.dynamicmockups.com.
🖼️

What you set up once (admin)

For each product — Seedstick pack, seed packet, branded pot — you create one mockup template in the DynamicMockups web app. Upload a PSD or choose from 1,000+ library templates. Define the "print area" (where logos go). Assign it to the WooCommerce product. Done.

🔌

WordPress Plugin (free, from WordPress repo)

Install "Dynamic Mockups" from the WordPress plugin repository. Connect to your DynamicMockups account. Plugin adds a "Create Mockups" button to each WooCommerce product. Also enables customer-facing personalisation on the product page. Tracks personalised orders in the WooCommerce order panel — "View Mockup" and "Download Print File" links per order line.

What happens when a customer uploads their logo
1
Customer uploads logo on product page

PNG, JPG, or WebP. The DynamicMockups WordPress plugin handles the upload UI directly on the WooCommerce product page. No redirect, no third-party site.

↓
2
Plugin calls the DynamicMockups Render API

A POST request to https://app.dynamicmockups.com/api/v1/renders is sent with the mockup template UUID (the product's template) and the customer's uploaded artwork URL. This is the API call — takes under 2 seconds in normal conditions.

↓
3
API renders the image and returns a URL

DynamicMockups Photoshop rendering engine places the logo into the print area on the product mockup, applies blending and positioning, and returns a URL of the rendered image. Output: PNG (default), JPG, or WebP. High resolution.

↓
4
Customer sees the rendered preview — live on the page

The plugin displays the returned image on the product page. No page reload. Customer sees their logo on the Seedstick pack (or whatever product). They can re-upload a different logo, see the new preview, then proceed to cart.

↓
5
Cart stores the personalised product + print file

The customised design is attached to the cart item. When the order is placed, WooCommerce stores both the rendered mockup image and the original print-ready file with the order.

↓
6
Your team downloads the print file from the WooCommerce order

In the WooCommerce order panel, each personalised line item shows two links: "View Mockup" (the preview image) and "Download Print File" (the print-ready file, named with the layer/position so your team knows exactly where to print). No more chasing Sandeep for artwork files on sub-£250 orders.

The API call — what it looks like
// POST https://app.dynamicmockups.com/api/v1/renders
// This fires when a customer uploads their logo on SowEasy
 
{
  "mockup_uuid": "[your-seedstick-template-uuid]", // set up once per product
  "export_options": {
    "image_format": "png",
    "image_size": 1200 // preview size in pixels
  },
  "smart_objects": [
    {
      "uuid": "[print-area-smart-object-uuid]", // the logo zone on the template
      "asset": {
        "url": "https://soweasy.com/uploads/customer-logo.png", // customer's file
        "fit": "contain" // logo scales to fit print area cleanly
      }
    }
  ]
}
 
// Response returns:
// { "data": { "export_path": "https://...rendered-image.png" }, "success": true }

DynamicMockups — what to know before you commit

  • Free plan: 50 renders. For a live trade store, you need a PRO plan (~$19/month). Included in our scope — we set this up for you.
  • The plugin produces a lifestyle-style preview (logo on product in a scene). It does not generate a print-ready press file from scratch — that's a different tool (like Zakeke). But for sub-£250 self-service orders, a clean visual preview + the customer's original artwork file downloaded from the order is all your print team needs.
  • Print-ready export: DynamicMockups does have a Render Print Files API (separate endpoint). We can enable this for orders that need a pre-masked print file. Worth discussing in the build phase.
  • Custom PSD templates: you can upload your own product PSDs (Seedstick pack artwork, branded pot artwork etc). Takes about 30 minutes per product template to set up.
