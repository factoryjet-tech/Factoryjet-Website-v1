## 1. REPOSITORY & STACK

- **Framework:** Next.js 16.1.3 with `output: 'export'` → fully static site, no SSR, no API routes
- **Language:** TypeScript
- **Styling:** Tailwind CSS 3.4
- **UI:** React 19
- **Animation:** GSAP + Framer Motion (both installed — duplicate, see Known Issues)
- **Package manager:** npm
- **Node:** match `.nvmrc` if present, otherwise LTS

**Build commands:**
```
npm install
npm run build       # runs scripts/generateSitemap.cjs as part of build
npm run dev
```

**Static-export implications:**
- No `getServerSideProps`, no API routes, no middleware-based personalisation.
- `next/image` production optimisation is disabled (see Issue #7).
- Every route must be statically renderable at build time.

## 4. DESIGN SYSTEM — NON-NEGOTIABLE

**⚠️ These rules override anything in `FactoryJet_Design_System_v1_0_Complete.md`. That file is historical reference only. The rules below are current.**

### 4.1 Fonts — Clash Display + Inter only

| Use | Font | Weight |
|---|---|---|
| All headings (h1–h6, hero) | **Clash Display** | 600–700 |
| All body, UI, buttons, labels | **Inter** | 400–600 |

- **Do NOT use** Poppins, Open Sans, or any other font family anywhere.
- Load fonts via `next/font` only. No `<link>` tags in `<head>` for fonts.
- Fonts must resolve via `<head>`, not `<body>` (see Issue #24 for UK layout fix).

### 4.2 Colors

| Token | Hex | Use |
|---|---|---|
| Primary (Jet Blue) | `#0052CC` | CTAs, links, primary emphasis |
| Secondary (Jet Orange) | `#FF6B35` | Accent, secondary CTAs, hover |
| Accent (Jet Green) | `#10B981` | Success, pricing highlights |
| Dark | `#0a0f1c` | **Non-hero dark sections only** |

Text neutrals follow the v1.0 scale: Navy `#0F172A`, Slate `#334155`, Gray `#64748B`, Light `#E2E8F0`, White `#F8FAFC`.

### 4.3 Hero sections — MUST be light (site-wide)

- **No dark hero sections anywhere on factoryjet.com.** Applies to all regions (India, UK, US, UAE) and all page types (homepage, service, city, industry, pricing, blog).
- Heroes must use white, light, or brand-tinted (blue/orange light tint) backgrounds.
- Bold typography, modern layout, generous whitespace.
- **Scoping note:** This rule is specific to the factoryjet.com repo. The separate UK city-page build project at `~/Downloads/FactoryJet UK Website/factoryjet-uk-pages` uses a dark `#0a0f1c` hero — do not cross-contaminate the two.
- Dark sections are allowed elsewhere on a page (mid-page CTA band, footer) — just not the hero.

### 4.4 Anti-slop rules

- No gradient text.
- No glassmorphism except in the `FinalCTA` component (maximum one instance per page).
- No particle systems, no spinning counters, no rainbow gradients.
- No AI-generic aesthetics — no bubbly blobs, no generic stock illustrations.
- 60-30-10 color rule enforced.

### 4.5 Content visibility (SEO-critical)

- **All primary content must render expanded and visible in the initial HTML.** No JS accordions, tabs, or "Read more" toggles hiding primary copy.
- **FAQ sections: static HTML only.** AI crawlers (GPTBot, ClaudeBot, PerplexityBot, Google-Extended, anthropic-ai) do not execute JavaScript. Use native `<details>`/`<summary>` or render fully open.
- Use `content-visibility: auto` for performance. CSS containment (`contain-intrinsic-size`) to keep CLS = 0.

### 4.6 2025 web design trends (taste guidelines)

- Strong typographic hierarchy (Clash Display at display sizes carries the page)
- Minimalist, generous whitespace
- Bento grid layouts for features and stats
- Asymmetric compositions (break the 12-col grid deliberately)
- Scroll-based animations via GSAP ScrollTrigger (subtle, not gimmicky)
- Micro-interactions on hover/focus
- Video-first content where it earns its place (no autoplay sound)
- AI-powered personalisation signals only when real, never performative
- Mobile-first always

### 4.7 Lighthouse targets

| Metric | Target |
|---|---|
| Performance | 90+ |
| SEO | 100 |
| Accessibility | 90+ |
| Best Practices | 95+ |

Gate any PR that drops any public page below these.

## 5. DEPLOYMENT WORKFLOW

- **Hosting:** Cloudflare Pages
- **Auto-deploy:** every `git push origin NextJS`
- **Cache:** Cloudflare Cache Rule "Cache Static Site HTML" — HTML pages cached at edge with 1-month Edge TTL, 4-hour Browser TTL. Status code TTL overrides (added 2026-04-20) prevent non-2xx responses from getting stuck:
  - 404 → No cache (revalidates on every hit)
  - 301 → No cache (future `_redirects` changes take effect immediately)
  - 302 → No cache
  - 500–526 range → No cache (origin errors never cached long-term)

  Any change to redirects or removal of broken URLs self-heals on next request — no manual cache purge required.
- **CDN/WAF:** Cloudflare — AI crawler user agents (GPTBot, ClaudeBot, PerplexityBot, anthropic-ai, Google-Extended) must remain allowlisted. Do not enable Bot Fight Mode on this zone.
- **Current adapter:** `@cloudflare/next-on-pages` (deprecated — OpenNext migration planned, Issue #21)

**Deploy sequence for any code change:**
1. Edit locally.
2. `npm run build` — must complete cleanly. Verify sitemap regen output in console.
3. `git add` + `git commit` (conventional commit style).
4. `git push origin NextJS`.
5. Watch Cloudflare Pages deploy log. Smoke-test the affected URL.
6. If a new route was added, confirm it appears in the regenerated sitemap and submit to GSC if strategic.

**Rollback:** Cloudflare Pages dashboard → Deployments → "Rollback to this deployment" on the last known-good build. Use this before trying to hotfix a broken `NextJS` head.

**Branch discipline:**
- `NextJS` IS the production branch. Push directly only when the commit is production-ready.
- For larger changes, work on a short-lived feature branch and merge via PR.
- Never push `.env*` files. Keep secrets in Cloudflare Pages environment variables.

## 9. OPERATIONAL RULES FOR CLAUDE CODE

Read these before every session.

1. **One prompt, one command.** One surgical change per prompt. Wait for confirmation before the next.
2. **Always `cat` the target file first** before editing. Never assume file contents.
3. **Surgical prompts only.** Name the exact file, exact change, and add an explicit guard: *"DO NOT touch layout, styling, animations, or any other section."*
4. **Session drift.** If the session has been open for ~30+ minutes or 40+ turns, restart: `/exit`, then `cd ~/FactoryJet/website && claude`.
5. **Commit discipline.** Every logical change is its own commit. Format: `type: short summary` (e.g. `fix: correct UK header links`, `feat: add Bristol city page`, `perf: lazy-load GSAP`).
6. **Design system is a hard constraint.** If a design prompt produces gradient text, glassmorphism outside FinalCTA, a dark hero, or Poppins/Open Sans anywhere — reject and regenerate.
7. **Static content rule.** FAQs, primary copy blocks, and key value props must be in the rendered HTML, not injected by client JS.
8. **Before adding a dependency**, check whether an existing one covers it. Prefer removing to adding.
9. **Sitemap awareness.** New routes must be picked up by either the dynamic UK `route.ts` sitemap or `scripts/generateSitemap.cjs` on next build. Routes missing from both is a bug.
10. **Conversion tracking is sacred.** Do not modify `src/utils/gtm.ts` without an explicit instruction.
11. **Region separation.** UK, US, UAE, and India have separate content, pricing, and sometimes separate components. Do not share across regions without instruction.
12. **Never commit secrets.** `.env*`, Firebase keys, MCP tokens, Google Ads API keys. Use Cloudflare Pages env vars.
13. **Pre-push checklist:** `npm run build` passes → visual smoke test in `npm run dev` → Lighthouse spot-check on the changed page if it's public-facing.
